# Matching benchmark on real Penn class schedules

Generated by `python -m app.matching.evaluate --penn` (23 minutes, OR-Tools 9.15.6755, Darwin arm64). Raw data: [`benchmark_penn_results.json`](benchmark_penn_results.json).

**Students are simulated, but their class schedules are real:**
- **Source:** meeting times for every section of 15 large Penn courses in 2026C (Fall 2026), from Penn Labs Penn Course Plan public API (penncourseplan.com/api/base), fetched 2026-11-18.
- **Pools:** each pool is one course's matching pool. Every simulated student takes that course plus 3 others from the list.
- **Sections:** each student registers for one section per activity (lecture, recitation, lab), weighted by section capacity and avoiding time conflicts.
- **Free time (the modelling assumption):** of the hours they're not in class (08:00–22:00), each student marks 6–14 hours a week as free, in 1–3 hour blocks. Evenings are likelier than daytime, and weekends least likely.
- **Preferences:** goal, pace and group size use the same mix as the main benchmark.
- **Trials:** paired, so all three algorithms see the same students in every trial, and each course has its own seeds.

## Against simpler strategies (all courses, 200 paired trials)

- **random:** shuffle and cut into groups of 4
- **first_come:** a sign-up sheet; join the first group with room that still has shared time
- **clustering:** balanced k-means on free time into groups of about 4, with greedy repair
- **greedy / local_search:** the baselines that seed the ILP

## Limitations

- The class schedules are real, but the students and the free hours they mark are simulated. These are algorithm comparisons, not usage results.
- Real course combinations aren't random: majors cluster. Each student here takes 3 random other courses from the list.
- An hour counts as busy if any class meeting overlaps it, so a 10:15–11:14 class blocks two grid hours.
