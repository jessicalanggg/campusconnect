# Load test

Generated by `python -m loadtest.run --students 500` against the real API (4 uvicorn worker processes) and PostgreSQL, on Darwin arm64. Students' free time comes from real Penn Fall 2026 class schedules (`app/matching/penn_schedules.py`).

**2,795 requests in 100s**. Each phase fires all of its requests together (up to 1584 per phase), with at most **100 in flight at once**. Server errors (5xx): **0**. Deadlocks in the database log: **0**. Worker restarts: **0**. Transport failures: **0**.

Matching-round latency includes the full solve (greedy, local search and ILP) for the waiting pool. Requests that land while a round holds the course's advisory lock wait for it, which shows up in their p95/p99.

These latencies are measured at saturation: 100 clients at once against 4 workers on one laptop, with argon2 password hashing in the sign-up burst. They show queueing under overload, not typical response times.
